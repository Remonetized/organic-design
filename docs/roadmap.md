# GitBan Roadmap

This is a parking place for ideas that may become useful after the template is used in real projects. Nothing here is mandatory.

## Good Candidates For v2

- Optional AI code review workflow that comments on PRs without blocking merge.
- Project bootstrap script for creating fields, variables, labels, and recommended settings from the CLI.
- Branch protection or ruleset setup guide once real CI checks exist in a fork.
- Cross-platform CLI helpers for bash/zsh alongside the PowerShell helpers.
- More helpful failure diagnostics when Project automation cannot find a board, field, option, or linked issue.
- Release/versioning workflow for projects that need tagged releases.
- Lightweight metrics or reporting docs for teams that want delivery visibility without extra meetings.

## Ideas To Avoid Until Proven Needed

- More board statuses.
- Mandatory AI review gates.
- Auto-stale or auto-archive rules.
- Complex branch naming enforcement.
- Scrum-style ritual tracking that duplicates what issues, PRs, and the board already show.

## Feedback Loop

When a fork reveals friction:

1. Capture the problem as an issue.
2. Fix it in the fork if the need is project-specific.
3. Port it back to the template only if it improves the general workflow.
4. Update docs and automation together.
